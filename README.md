# DataCleaner

Сервис, который сам отправляет требования об удалении ваших персональных данных из брокеров,
people-search сайтов, маркетинговых баз и поисковой выдачи — и следит за сроками. Письма — по
152-ФЗ, GDPR и CCPA; **автопилот** отправляет черновики и напоминания без вашего участия;
**AI-помощник** знает нормы и вашу статистику (без ПД). Подключение почты — один экран:
**адрес + пароль**, сервер и порт подбираются сами; реальная отправка включается тумблером.

Два варианта запуска:

| Вариант | Что это | Где данные | Зачем |
|---|---|---|---|
| **A. `datacleaner.html`** | один HTML-файл, ~242 КБ, без сервера и установки | `localStorage` вашего браузера | открыть с телефона или ПК, ничего не ставить; письма копируются/открываются в вашей почте |
| **B. `app/` (FastAPI)** | сервер на Python 3.11+, SQLite, шифрование Fernet, SMTP, AI | SQLite, ПД зашифрованы | личное использование дома/на VPS, основа продукта |

Обе версии — один и тот же интерфейс: `datacleaner.html` автоматически определяет, отдаёт ли
его FastAPI, и в этом случае переключается из режима `local` в режим `server` (бейдж в шапке).

## 1. Архитектура и решения

1. **Одна кодовая база фронтенда**: исходники в `frontend/` (шаблон + 4 JS-файла), сборка
   `python tools/build_html.py` склеивает их в автономный `datacleaner.html` и в `app/static/index.html`.
2. **Чистое ядро** (`01-core.js` ↔ `app/letters.py`, `app/stats.py`) не знает про DOM и сеть — поэтому
   его можно тестировать (pytest на сервере + «Самопроверка» в браузере).
3. **Слой API** (`Api` в браузере) имеет две реализации: `local` (localStorage) и `server` (REST).
   UI не знает, где лежат данные.
4. **ПД всегда отдельно от метаданных**: в SQLite тексты писем и профиль лежат в BLOB'ах Fernet,
   статусы и даты — открытым текстом (нужны для статистики, ПД не содержат).
5. **Срок 30 дней — вычисляемое поле**: `deadline_at` ставится при отправке и обнуляется при
   «Повторить», поэтому просрочки не «залипают».
6. **Никакого трекинга получателя**: письма — `text/plain`, без пикселей, внешних картинок и
   редирект-ссылок. Учитываются только ответы и подтверждения удаления.
7. **AI изолирован**: запросы с email/телефоном/номером документа блокируются локально до
   сети, ключ живёт только в `.env` сервера (или в localStorage в браузерном режиме).
8. **DRY_RUN=1 по умолчанию** — весь путь отправки проверяется, но письма не уходят.
9. **Автопилот в процессе приложения**: фоновая задача `asyncio` внутри FastAPI (без Celery и Redis —
   бесплатный хостинг их не тянет). Раз в `interval_minutes` она отправляет новые черновики
   (`auto_send`) и повторные требования по молчащим операторам (`followup_enabled`, по умолчанию
   через 30 дней, ровно один раз на запрос — без спама).
10. **Почта настраивается в интерфейсе**: SMTP-хост, порт, логин и «пароль приложения» вводятся в
   разделе «Автопилот» и лежат в `kv` **зашифрованными Fernet**; в браузер пароль не возвращается
   никогда (`has_password: true/false`). Переменные окружения `SMTP_*` остаются как альтернатива:
   значение из интерфейса приоритетнее.
11. **Письма-жалобы и напоминания собираются локально** (`app/letters.py`, `app/knowledge.py`), без
   обращения к LLM: жалоба в Роскомнадзор для RU-сервисов, DPA по Art. 77 GDPR — для остальных.
12. **Сроки по 152-ФЗ точные**: требование в письме ссылается на ст. 21 (уничтожение — до 30 дней), а на запрос оператор обязан ответить в 10 рабочих дней по ст. 20 (продление не более чем на 5). Таймер в интерфейсе считает 30 дней — это срок уничтожения данных, зафиксированный в требовании.

## 3. Запуск на ПК

### Вариант A — без установки (30 секунд)

1. Скачайте `datacleaner.html`.
2. Откройте двойным щелчком в любом браузере (Chrome, Firefox, Safari, Edge).
3. Готово. Бейдж в шапке покажет `LOCAL` — данные лежат в localStorage этого браузера.

Проверка работоспособности: кнопка **«Самопроверка»** в шапке → «20 из 20 проверок пройдено».

### Вариант B — сервер

```bash
# 1. Python 3.11+ и зависимости
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Конфигурация
cp .env.example .env
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
#   → вставьте вывод в .env как DATA_KEY=...

# 3. Запуск
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Откройте <http://127.0.0.1:8000>. Бейдж в шапке — `SERVER`.
Документация API — <http://127.0.0.1:8000/docs>.

Пересборка интерфейса после правок `frontend/`:

```bash
python tools/build_html.py
```

Тесты:

```bash
pytest -q          # 26 passed
```

## 4. Запуск с телефона

### A. Файл без сервера

1. Перекиньте `datacleaner.html` на телефон: Telegram «Избранное» → скачать, iCloud/Google Drive,
   кабель, почта — любым способом.
2. **Android**: откройте файл из «Загрузок»/файлового менеджера → «Открыть с помощью» → Chrome.
   Либо в Chrome в адресной строке: `file:///storage/emulated/0/Download/datacleaner.html`.
3. **iPhone**: файл в «Файлах» → нажать → «Поделиться» → «Открыть в Safari».
   Если Safari открывает пустую страницу — сохраните файл в «Файлы → На iPhone» и откройте оттуда.
4. Данные будут храниться в браузере телефона. Не открывайте приватную вкладку: в ней
   `localStorage` недоступен (приложение предупредит и будет держать данные только в памяти).

> Ограничения мобильного режима: письма не отправляются автоматически (это и не нужно) —
> нажимайте «Скопировать письмо» или «Открыть в почте», отправляйте из Gmail/Яндекс.Почты.

### B. Сервер, доступный с телефона

**В одной Wi-Fi сети (домашний ПК):**

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
hostname -I        # Linux/macOS: узнать IP, например 192.168.1.42
ipconfig           # Windows: «IPv4-адрес»
```

На телефоне: `http://192.168.1.42:8000`. Если не открывается — разрешите Python в брандмауэре
(Windows: «Разрешить приложению доступ к сети»).

**Через интернет (бесплатно, для личного пользования):**

```bash
# временный публичный туннель без регистрации
pip install cloudflared    # или скачать бинарник с github.com/cloudflare/cloudflared
cloudflared tunnel --url http://localhost:8000
```

Cloudflare выдаст `https://что-то.trycloudflare.com` — открывайте с телефона. Ссылка живёт,
пока работает процесс. Для постоянного адреса — деплой из раздела 7.

**Безопасность:** серверная версия рассчитана на одного пользователя. Перед публикацией в
интернет поставьте перед ней Basic Auth (например, через Caddy/Nginx) или добавьте
токен-авторизацию — см. раздел 7.

## 5. Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `DATA_KEY` | да (сервер) | ключ Fernet для шифрования ПД. Без него создаётся локальный `.datacleaner.key` (только для разработки). **Потеря ключа = потеря данных, это by design.** |
| `DRY_RUN` | нет | `1` (по умолчанию) — письма не уходят; `0` — реальная отправка |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | для отправки | SMTP-сервер и ящик. Для Gmail/Яндекса/Mail.ru нужен **пароль приложения**, а не пароль аккаунта. На бесплатном Render порты 465/587 закрыты — там нужен HTTPS-API или порт 2525 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | для входа через Google | OAuth-клиент (Web application) с redirect URI `<домен>/api/mail/google/callback` и включённым Gmail API |
| `PUBLIC_BASE_URL` | нет | внешний адрес сервиса — из него строится redirect URI |
| `BREVO_API_KEY`, `RESEND_API_KEY` | для отправки на PaaS | ключ HTTPS-API провайдера. С ключом транспорт выбирается сам, SMTP не нужен |
| `EMAIL_FROM`, `EMAIL_FROM_NAME` | с HTTPS-API | подтверждённый у провайдера адрес отправителя и его имя |
| `MAIL_PROVIDER` | нет | `brevo` / `resend` / `smtp` — принудительный выбор транспорта |
| `SMTP_SSL` / `SMTP_STARTTLS`, `SMTP_FROM_NAME` | нет | `465`+SSL (`SMTP_SSL=1`) или `587`+STARTTLS (по умолчанию) |
| `LLM_API_KEY` | для AI | ключ OpenAI-совместимого провайдера |
| `LLM_BASE_URL` | для AI | base URL провайдера, запрос идёт на `{LLM_BASE_URL}/chat/completions` |
| `LLM_MODEL` | для AI | точный ID модели из таблицы провайдера |
| `LLM_TIMEOUT`, `LLM_MAX_TOKENS` | нет | по умолчанию 60 с и 800 токенов |
| `CORS_ORIGINS`, `LOG_LEVEL` | нет | `*` и `INFO` по умолчанию |
| `DATACLEANER_DB` | нет | путь к файлу SQLite (постоянный диск на хостинге) |

**AI-провайдер (пример настройки, ключ вы вписываете сами):**

```dotenv
LLM_API_KEY=<ваш ключ>
LLM_BASE_URL=https://tokenlavka.com/v1
LLM_MODEL=gpt-6-luna
```

Провайдены проверены живьём: `POST https://tokenlavka.com/v1/chat/completions` с
`Authorization: Bearer <ключ>` и моделью `gpt-6-luna` отвечает, CORS открыт
(`access-control-allow-origin: *`), поэтому браузерная версия тоже работает без сервера.
Список моделей: `GET https://tokenlavka.com/v1/models`. Ключ в этом репозитории не хранится:
`.env` в `.gitignore`, в браузерном режиме ключ кладётся в localStorage кнопкой
«AI-помощник → Настройки».

## 5a. Автопилот: как включить реальную отправку

Писем касаются две вещи: **почтовый транспорт** (откуда отправляем) и **DRY_RUN** (разрешение
отправлять вообще). Настраиваются отдельно, проверяются по шагам ниже.

### Шаг 1. Какой транспорт выбрать — зависит от хостинга

| Где запущено | SMTP (465/587) | HTTPS-API (Brevo/Resend) |
|---|---|---|
| Свой ПК / VPS / домашний сервер | ✅ работает | ✅ работает |
| Render **бесплатный** | ❌ **заблокирован** (порты 25/465/587 закрыты платформой) | ✅ работает |
| Render платный | ✅ работает (кроме порта 25) | ✅ работает |

Ограничение бесплатного Render — официальное: «Free web services can't send outbound network
traffic on ports 25, 465, or 587» ([render.com/docs/free](https://render.com/docs/free)). Порт 25
закрыт у Render на всех тарифах. Поэтому на бесплатном хостинге SMTP-путь физически не подключается:
соединение висит и падает по таймауту, как бы правильно ни был введён пароль приложения.
В DataCleaner для этого случая есть второй транспорт — **HTTPS-API провайдера** (обычный HTTPS, порт 443).

### Шаг 2. «Просто войти в почту»: адрес + пароль (основной путь)

В разделе **«Автопилот»** → карточка **«Просто войти в почту»**: два поля — `Почта` и `Пароль`,
кнопка «Войти и проверить». Ничего больше указывать не нужно.

* Сервер и порт определяются по домену адреса автоматически:

  | Домен | Сервер | Порт | Шифрование |
  |---|---|---|---|
  | gmail.com / googlemail.com | smtp.gmail.com | 587 | STARTTLS |
  | yandex.ru / ya.ru / yandex.com | smtp.yandex.ru | 465 | SSL |
  | mail.ru / bk.ru / inbox.ru / list.ru | smtp.mail.ru | 465 | SSL |
  | outlook.com / hotmail.com / live.com | smtp-mail.outlook.com | 587 | STARTTLS |
  | любой другой | smtp.<домен> | 587 | STARTTLS |

  Строка под формой сразу показывает, что подобрано (`Определено: smtp.yandex.ru:465 (SSL)`).
* «Войти и проверить» подключается к серверу, проходит `EHLO/STARTTLS/AUTH` и отвечает по-русски:
  успех, «сервер отклонил логин или пароль (535)» или «хостинг блокирует порт — нужен 2525 / Google».
* Настройки сохраняются **только при успешном входе**. Если пароль с опечаткой — прежний рабочий
  вход не затирается, письма не начинают «делать вид», что отправка настроена.
* Пароль не возвращается ни в API, ни в браузер (только `has_password: true/false`), в базе — Fernet.
* Кнопка **«Где взять пароль?»** — честная таблица: что именно принимает каждый провайдер.

**Важное ограничение, которое не обойти.** Gmail, Яндекс, Mail.ru и Outlook не пускают сторонние
приложения по обычному паролю от аккаунта — они требуют **«пароль приложения»** (16 символов,
выдаются в настройках безопасности за минуту):

* Gmail — <https://myaccount.google.com/apppasswords> (нужна включённая 2FA);
* Яндекс — <https://id.yandex.ru/security/app-passwords>;
* Mail.ru — <https://account.mail.ru/user/2-step-auth/passwords>;
* Outlook — <https://account.live.com/proofs/AppPassword>.

Это защита провайдеров, а не ограничение DataCleaner: обычный пароль от почты они отклоняют
на уровне SMTP (`535 authentication failed`), и никакая программа не может это обойти — иначе
любой сервис мог бы читать чужую почту, зная пароль. Поэтому в форме можно вводить оба варианта:
если провайдер принимает обычный пароль (свой домен, корпоративный сервер, некоторые хостинги
почты) — он сработает; если нет — форма прямо скажет, что нужен пароль приложения.

Два пути, где пароль вообще не нужен:

* **«Войти через Google»** (шаг 2a) — обычный пароль Google вводится на странице Google, а не в
  приложении; сервис получает только право отправлять письма;
* **HTTPS-API провайдера** (шаг 2b) — Brevo/Resend, ключ вместо пароля.

На **бесплатном Render** SMTP-порты 465/587 закрыты платформой, поэтому «Просто войти» там
честно ответит подсказкой про порт 2525 и Google: на этом тарифе реальная отправка идёт через
SMTP-релей на 2525 (Brevo/SMTP2GO/SendGrid) или через Google OAuth.

### Шаг 2a. Вариант «Войти через Google» (самый простой, без паролей приложений)

Пользователь вводит **свой обычный пароль Google** на странице Google — приложение его не видит и не
хранит. Письма уходят с вашего Gmail через **Gmail API по HTTPS (порт 443)**, поэтому это работает и
на бесплатном Render, где SMTP закрыт. Никаких «паролей приложений», SMS и мессенджеров.

**Один раз настраивается владельцем сервиса (5 минут):**

1. [console.cloud.google.com](https://console.cloud.google.com/projectcreate) → создать проект.
2. **APIs & Services → Library** → найти **Gmail API** → **Enable**.
3. **OAuth consent screen** → тип **External** → заполнить название и адрес поддержки →
   в **Test users** добавить свой Gmail (пока приложение в режиме Testing этого достаточно) →
   scope `https://www.googleapis.com/auth/gmail.send`.
4. **Credentials → Create credentials → OAuth client ID → Web application** →
   **Authorized redirect URI**: `<ваш домен>/api/mail/google/callback`
   (для этого проекта — `https://datacleaner-st2u.onrender.com/api/mail/google/callback`).
5. Render → **Environment**:
   - `GOOGLE_CLIENT_ID` = `…apps.googleusercontent.com`
   - `GOOGLE_CLIENT_SECRET` = `GOCSPX-…`
   - `PUBLIC_BASE_URL` = `https://datacleaner-st2u.onrender.com` (чтобы redirect URI считался точно)
6. Save → сервис перезапустится.

**Дальше в интерфейсе:** «Автопилот» → карточка **«Вход через Google»** → «Войти через Google» →
в окне Google ввести пароль и разрешить отправку писем → статус станет «письма идут через Google»,
в `/api/health` появится `"mail_transport": "google"`.

Особенности:

* токены (access + refresh) хранятся **зашифрованными Fernet** в таблице `kv` и никогда не отдаются в браузер;
* в режиме **Testing** токен живёт 7 дней — потом достаточно снова нажать «Войти через Google»;
  публикация приложения в Google снимает это ограничение;
* отключить доступ можно кнопкой «Отключить» в интерфейсе или в
  [настройках аккаунта Google](https://myaccount.google.com/permissions);
* письма по-прежнему только `text/plain`, без пикселей и трекинга.

**Если у вас уже есть client ID, а секрета нет.** `GOOGLE_CLIENT_ID` без `GOOGLE_CLIENT_SECRET`
не работает: сервис честно показывает «нужна настройка» (`configured:false` в `/api/mail/google/status`).
Секрет лежит в том же месте, где создавался клиент:

1. [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials) →
   в разделе **OAuth 2.0 Client IDs** открыть клиент
   `13344963095-…apps.googleusercontent.com`;
2. справа — **Client secret** (`GOCSPX-…`), при необходимости **Add secret** / **Reset secret**;
3. там же в **Authorized redirect URIs** добавить ровно
   `https://datacleaner-st2u.onrender.com/api/mail/google/callback`;
4. Render → **Environment** → `GOOGLE_CLIENT_SECRET` = `GOCSPX-…` → Save;
5. `curl -H "X-Access-Token: …" https://datacleaner-st2u.onrender.com/api/mail/google/status`
   → должно стать `"configured": true, "mode": "testing"`.

Секрет — это пароль приложения OAuth: в чат и в репозиторий его писать не нужно, только в переменные
окружения Render.

Переменные: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `PUBLIC_BASE_URL`, опционально
`GOOGLE_REFRESH_TOKEN` (если вход через браузер не нужен) и `GOOGLE_ACCESS_TOKEN` (для отладки).

### Шаг 2b. Вариант «HTTPS-API» (Brevo/Resend, без Google-аккаунта)

Бесплатно и без домена:

1. Зарегистрируйтесь в [Brevo](https://www.brevo.com) (free: 300 писем в день).
2. **Settings → Senders & IP → Senders** → добавьте свой адрес и подтвердите его письмом
   (это адрес отправителя, домен не нужен).
3. **Settings → SMTP & API → API Keys** → создайте ключ (`xkeysib-…`).
4. В Render: **Environment → Add Environment Variable**:
   - `BREVO_API_KEY` = `xkeysib-…`
   - `EMAIL_FROM` = подтверждённый адрес (например `you@gmail.com`)
   - по желанию `EMAIL_FROM_NAME` = `DataCleaner`
5. Save → сервис перезапустится. В разделе «Автопилот» статус станет
   «Отправка через HTTPS-API: Brevo API (HTTPS, 300 писем в день бесплатно)».
6. Кнопка «Отправить тест себе» отправит реальное письмо через API (при `DRY_RUN=0`).

Альтернатива — [Resend](https://resend.com): `RESEND_API_KEY` + `EMAIL_FROM`. Без своего домена
Resend отправляет только на адрес владельца аккаунта, поэтому для писем брокерам нужен
подтверждённый домен. Для проверки «письмо реально уходит» этого достаточно.

`MAIL_PROVIDER=brevo|resend|smtp` заставляет выбрать транспорт вручную, если заданы оба ключа.

### Шаг 2c. Вариант «SMTP» (свой ПК/VPS или платный Render)

В интерфейсе, раздел **«Автопилот»**:

1. Выберите провайдера (Gmail / Яндекс / Mail.ru / Outlook или «Другой сервер»).
2. Логин и **«пароль приложения»** (не пароль от почты!) + адрес отправителя.
   Gmail: `smtp.gmail.com:587` + STARTTLS. Яндекс: `smtp.yandex.ru:465` + SSL.
3. «Проверить соединение» (`EHLO/STARTTLS/AUTH` без письма), затем «Отправить тест себе».

На бесплатном Render вместо 465/587 укажите **порт 2525** у провайдера, который его поддерживает
(Brevo `smtp-relay.brevo.com:2525` + STARTTLS, SendGrid `smtp.sendgrid.net:2525`): платформа
блокирует только 25/465/587.

Пароль SMTP шифруется Fernet и хранится в `kv`; в API и в браузер он не возвращается
(только `has_password: true/false`). Отправка идёт с вашего ящика, а не «от сервиса» —
оператор видит обычное письмо от частного лица.

### Шаг 3. Выключить DRY_RUN

Пока `DRY_RUN=1`, автопилот собирает письма, пишет события и **не отправляет** — это защита от
случайных писем живым компаниям. Включить реальную отправку:

* **в интерфейсе**: «Автопилот» → карточка **«Реальная отправка»** → переключатель
  «Отправлять письма по-настоящему» (после подключения почты, с подтверждением). Статус виден рядом:
  `выключена (DRY_RUN)` / `включена`; переключатель перекрывает переменную окружения и сохраняется в базе;
* или Render → **Environment** → `DRY_RUN` = `0` → Save (сервис перезапустится);
* или в своём `.env`: `DRY_RUN=0`.

Проверка: `curl https://<ваш-сервис>/api/health` → `"dry_run": false`, `"mail_ready": true`,
`"mail_transport": "brevo"` (или `"smtp"`).

### Шаг 4. Режимы автопилота

* «Автоотправка черновиков» — новые запросы уходят сами, без нажатий.
* «Напоминания просроченным» — через N дней (по умолчанию 30) одно повторное требование на запрос.
* Интервал проверки — по умолчанию 15 минут.
* «Прогон сейчас» запускает проход немедленно и показывает журнал: сколько отправлено,
  сколько напоминаний, по каким брокерам без email письмо нужно отправить через форму.

### Если письма всё равно не уходят

| Симптом | Причина | Что делать |
|---|---|---|
| Висит ~20–60 с и падает по таймауту | хостинг блокирует SMTP-порт | HTTPS-API (шаг 2a) или порт 2525 |
| «Сервер отклонил логин или пароль» | пароль аккаунта вместо пароля приложения | создать пароль приложения |
| «ключ не принят (401/403)» | неверный ключ Brevo/Resend или адрес отправителя не подтверждён | проверить ключ и подтвердить sender |
| «Адрес отправителя не подтверждён» | `EMAIL_FROM` не верифицирован у провайдера | подтвердить адрес в кабинете |
| В журнале «через форму: N» | у брокера нет email (Spokeo, Google) | отправить письмо через форму на сайте |

Всё это же видно в интерфейсе: «Автопилот» → строка статуса под формой и журнал внизу.

3. План **Free**, регион **Frankfurt**, Health Check Path — `/api/health`.
4. Environment:
   - `DATA_KEY` — сгенерируйте: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
   - `ACCESS_TOKEN` — любой код доступа, например `dc-` + 24 случайных символа
   - `DRY_RUN=1`
   - `DATACLEANER_DB=/data/datacleaner.db`
   - `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` — если нужен AI
   - `SMTP_*` — когда захотите реальную отправку (и `DRY_RUN=0`)
5. Deploy → дождитесь `Live` → откройте адрес вида `https://datacleaner-xxxx.onrender.com`.
   Приложение спросит **код доступа** — это значение `ACCESS_TOKEN`.
6. Проверка: `curl https://ваш-адрес/api/health` → `{"ok":true,"auth_required":true,...}`,
   а `/api/stats` без заголовка `X-Access-Token` отдаёт `401` — значит защита работает.

> **Про бесплатный план Render:** инстанс засыпает после 15 минут простоя (первый заход
> ~30–60 секунд) и **диск не постоянный** — SQLite обнулится при передеплое/рестарте.
> Для регулярного использования: экспорт JSON из раздела «Данные» либо внешняя Postgres
> (Neon/Supabase free), либо платный диск Render ($1–7/мес).
> **Про репозиторий:** Render API умеет собирать только публичные репозитории без установки
> GitHub App. Если нужен приватный — установите Render GitHub App в аккаунт, сделайте репозиторий
> приватным, и Render продолжит деплой по тому же сервису.

### 8.2 Безопасность до продакшена

- [ ] Аутентификация (пока её нет — сервер рассчитан на одного пользователя). Минимум —
      HTTP Basic Auth на прокси; лучше — magic-link вход и сессии в cookie (`HttpOnly`, `Secure`).
- [ ] HTTPS обязателен: `HSTS`, редирект с http.
- [ ] Rate limit на `/api/assistant` и `/api/requests/*/send` (иначе ключ LLM и SMTP-репутация сгорят).
- [ ] Резервные копии БД, но **зашифрованные**: сама БД уже содержит шифротекст, ключ — отдельно.
- [ ] `DATA_KEY` только в менеджере секретов (не в git, не в образе), ротация ключа = перешифровка.
- [ ] CSP без `unsafe-inline` (сейчас стили и скрипты инлайн — при выносе в файлы закройте и это).
- [ ] Логи без ПД: не логировать тела писем и профиль (в текущем коде так и есть).

### 8.3 Политика конфиденциальности и согласие

Готовые шаблоны: `docs/privacy-policy-template.md` и `docs/consent-template.md`.
Минимум, который нужно опубликовать на домене:

1. **Политика конфиденциальности** — какие данные собираем (ФИО, email, телефоны, город, год
   рождения, адрес), зачем (формирование запросов на удаление), как храним (шифрование Fernet),
   сколько храним (до удаления пользователем), кому передаём (SMTP-провайдер, LLM-провайдер —
   без ПД), как удалить (кнопка «Удалить всё» + запрос на email), права субъекта.
2. **Согласие на обработку ПД** — отдельный чекбокс при регистрации (в РФ согласие должно быть
   конкретным, предметным и информированным; ст. 9 152-ФЗ), с перечнем данных и целей.
3. **Уведомление в Роскомнадзор** об обработке ПД (для оператора ПД в РФ — обязательно до
   начала обработки, подаётся через портал РКН; для личного использования без передачи третьим
   лицам — не требуется).
4. **Cookie/трекеры** — в текущей версии их нет вообще (это преимущество, укажите это в политике).

### 8.4 Соответствие GDPR

- **Роли**: вы — контролёр ПД пользователя; SMTP- и LLM-провайдеры — процессоры → нужны DPA
  (Data Processing Agreement) и, при передаче за пределы ЕС, SCC + оценка рисков.
- **Правовое основание**: договор (ст. 6(1)(b)) + согласие на обработку (ст. 6(1)(a)) для
  специальных категорий, если появятся.
- **Минимизация**: собирать только то, что уходит в письмо; поля «адрес» и «год рождения» —
  опциональны (уже так).
- **Права субъекта**: доступ, исправление, удаление, переносимость (экспорт JSON — есть),
  возражение. Срок ответа — 1 месяц (ст. 12(3)); реализуйте кнопку «Экспорт» в интерфейсе
  (есть) и удаление аккаунта (есть «Удалить всё»).
- **Privacy by design**: шифрование ПД, отсутствие трекинга, отсутствие ПД в промтах LLM
  (реализовано фильтром) — это стоит явно описать в политике.
- **Data breach**: процесс уведомления надзорного органа в течение 72 часов (ст. 33).
- **DPO** не обязателен при текущем масштабе, но назначьте ответственного и укажите контакт.

### 8.5 Соответствие 152-ФЗ

- Локализация ПД россиян на территории РФ (ст. 18.1) → хостинг в РФ, если работаете как оператор
  на массовом рынке.
- Уведомление РКН, согласие, политика, назначение ответственного за организацию обработки ПД.
- Модель угроз и уровень защищённости по ПП № 1119 — при работе с ПД в коммерческом продукте
  потребуется определить УЗ и применить соответствующие меры (шифрование, разграничение доступа,
  журналирование).
- Не путать роли: **вы обрабатываете ПД пользователя**, чтобы помочь ему направить требования.
  Опишите это как отдельную цель обработки, не связанную с самими брокерами.

### 8.6 Развитие функционально

- Каталог брокеров с проверкой ссылок (краулер + ручная модерация), версии по странам.
- Автоматическое отслеживание ответов: отдельный почтовый ящик `replies@` + IMAP-парсинг
  (ответ → статус `responded`). Это «честная» альтернатива трекинг-пикселям.
- Генерация готовых PDF-заявлений для РКН/регуляторов, повторные напоминания по расписанию
  (APScheduler/Celery).
- Семейные аккаунты (несколько профилей), API для юристов и privacy-агентств.
- Мониторинг утечек (Have I Been Pwned API), проверка выдачи по своим данным (Google/Yandex API
  или ручные чек-листы — полный автоматический парсинг людей нарушает ToS поисковиков).
- Мобильное приложение-обёртка (PWA: добавить `manifest.json` + service worker к `datacleaner.html`).

| Модель | Как | Нюанс |
|---|---|---|
| Freemium | бесплатно: 5 запросов/мес, статистика, шаблоны; платно: неограниченно, автоотправка, напоминания, семейный профиль | самый понятный путь |

репутации, и юридически).

## 9. Что в этом проекте нельзя проверить без интернета/аккаунтов

1. **Точные URL форм и email брокеров.** Ссылки в `app/brokers.json` соответствуют типовым
   адресам opt-out, но сервисы их меняют, ограничивают по региону и требуют капчу. Поэтому в
   каждой карточке стоит плашка «проверить перед использованием» и поле `verify: true`.
   Как проверить: откройте карточку → «Открыть сайт» → найдите на сайте раздел
   «Privacy / Do Not Sell My Info / Opt-out»; для РФ-сервисов — «Политика в отношении обработки
   персональных данных», оттуда берите адрес оператора и вписывайте через «Свой сервис».
2. **Реальная отправка писем** требует вашего SMTP (пароль приложения) — в проекте по умолчанию
   `DRY_RUN=1`, письма не уходят. Проверяется по чек-листу в разделе 7.
3. **Ваш API-ключ AI** в файлы не попал: `.env` в `.gitignore`, значение подставляете сами.
   Работоспособность провайдера (`https://tokenlavka.com/v1`, модель `gpt-6-luna`, CORS) проверена
   живым запросом; ответ модели по 152-ФЗ в браузерном режиме получен.
4. **Юридическая сила шаблонов.** Письма — корректные по структуре и ссылкам на нормы, но это не
   юридическое заключение. Перед коммерческим запуском покажите шаблоны юристу по ПД.
