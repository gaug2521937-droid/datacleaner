# Согласие на обработку персональных данных + чек-лист соответствия

Два блока: (1) тексты, которые нужно разместить в продукте, (2) рабочий чек-лист перед
коммерческим запуском.

---

## 1. Тексты для интерфейса

### 1.1 Чекбокс согласия (обязательный, не предустановленный)

```text
[ ] Я согласен на обработку моего[ей] персональных данных: ФИО, адрес электронной почты,
    номер телефона, город, год рождения и (по моему выбору) почтовый адрес — в целях
    подготовки и направления требований об удалении данных, а также ведения статусов
    обращений. Данные хранятся в зашифрованном виде и удаляются по моему запросу.
    С порядком обработки ознакомлен(а): [Политика конфиденциальности].
```

Требования по РФ (152-ФЗ, ст. 9): согласие — конкретное, предметное, информированное,
сознательное; нельзя связывать согласие со всем договором; нельзя включать заранее
отмеченный чекбокс; должен быть механизм отзыва согласия.

### 1.2 Как отозвать согласие (кнопка и текст)

```text
Удалить все мои данные  [Удалить всё]

Нажимая «Удалить всё», я отзываю согласие на обработку персональных данных и требую удалить
профиль, запросы, историю изменений и созданные мной сервисы. Действие необратимо.
```

Реализовано в приложении: раздел **«Данные» → «Удалить всё»** (в серверной версии требует
ввода `DELETE`, эндпоинт `POST /api/wipe`).

### 1.3 Плашка «что мы не делаем» (для лендинга)

```text
— не продаём и не передаём ваши данные брокерам;
— не вставляем трекинг-пиксели и не отслеживаем, прочитал ли письмо получатель;
— не отправляем ваши ФИО, телефоны и email в AI-модели;
— не обещаем «гарантированное удаление»: результат зависит от оператора, наша задача —
  сделать процедуру корректной, срок соблюдаемым, а переписку — доказуемой.
```

## 2. Чек-лист перед коммерческим запуском

### 2.1 Данные и функциональность

- [ ] Все поля, которые не обязательны, помечены как необязательные (есть).
- [ ] Экспорт данных (JSON) работает и отдаётся пользователю по кнопке (есть).
- [ ] Полное удаление работает одной кнопкой, с подтверждением (есть).
- [ ] В письмах нет трекеров; в интерфейсе нет аналитических cookie (есть — их нет).
- [ ] PII-фильтр перед LLM работает и описан в политике (есть).
- [ ] Логи не содержат ПД: проверьте `LOG_LEVEL=DEBUG` и тела запросов перед релизом.
- [ ] Резервные копии БД шифруются или лежат на диске, доступном только сервису.

### 2.2 152-ФЗ (если работаете на рынке РФ как оператор ПД)

- [ ] Уведомление в Роскомнадзор об обработке ПД подано (до начала обработки).
- [ ] Политика опубликована на домене, ссылка есть в футере и в чекбоксе.
- [ ] Назначен ответственный за организацию обработки ПД, документы по ст. 18.1 есть.
- [ ] Определён уровень защищённости по ПП № 1119, применены меры (шифрование, доступы, журнал).
- [ ] Локализация: база с ПД россиян на территории РФ (ст. 18.1).
- [ ] Форма запроса субъекта (ст. 14) и срок 30 дней соблюдаются (в продукте — автоматически).
- [ ] Модель угроз и приказ о мерах защиты утверждены.

### 2.3 GDPR (если есть пользователи в ЕС)

- [ ] Определена роль: контролёр для данных пользователя; процессоры — SMTP, LLM, хостинг.
- [ ] Подписаны DPA с каждым процессором; для передачи вне ЕС — SCC + TIA.
- [ ] Реестр обработки (Record of Processing Activities) заведён.
- [ ] Реализованы права: доступ, экспорт, удаление, возражение; срок ответа ≤ 1 месяц.
- [ ] Процедура уведомления о утечке: оценка риска и уведомление органа в течение 72 часов.
- [ ] Privacy by design отражён в политике (шифрование, отсутствие трекеров, минимизация).
- [ ] Указан контакт для обращений по ПД (DPO или ответственный).
- [ ] Проверено: не обрабатываются специальные категории и данные детей.

### 2.4 CCPA/CPRA (если есть пользователи в Калифорнии)

- [ ] Описано, какие категории данных собираем и что **не продаём**.
- [ ] Есть ссылка/механизм «Do Not Sell or Share My Personal Information» — даже если продажи
      нет, публично заявите об этом.
- [ ] Срок ответа на запросы об удалении/доступе — 45 дней (продлеваемо ещё на 45).
- [ ] Проверка личности при запросах — минимально необходимый объём данных.

### 2.5 Продукт и инфраструктура

- [ ] HTTPS, HSTS, редирект с http.
- [ ] Аутентификация пользователей (сейчас ориентировано на одного пользователя).
- [ ] Rate limit на отправку писем и на AI-запросы.
- [ ] Мониторинг: доступность, ошибки SMTP, квота LLM.
- [ ] Инструкция «что делать при утечке» и контакты для сообщений о проблемах.
- [ ] Юристы посмотрели шаблоны писем (152-ФЗ / GDPR / CCPA) и политику.
